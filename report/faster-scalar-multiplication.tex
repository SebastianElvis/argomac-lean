\begin{abstract}
The ArgoMAC baseline uses an incomplete point-addition law and 92 digits in base $2-\omega$.
This report gives a complete 91-digit construction for BN254 G1.
An exact Eisenstein-norm proof establishes the digit bound.
A second Lean proof establishes complete Renes--Costello--Batina addition.
It covers ordinary addition, doubling, and inverse addition.
The construction uses the minimum adaptor count in the fixed bidegree $(2,2)$ Bosma--Lenstra family.
Lean 4.24 checks these results without a new axiom or compiler-trusted evaluation.
It also checks the 508-bit Lamport label order.
The matching Rust code uses the same law and garbles independent rows with Rayon.
\end{abstract}

\section{Contribution}

Let $r$ be the BN254 scalar modulus.
Let $\omega$ be the nontrivial cube root used by the G1 endomorphism.
Set $\beta=2-\omega$.
The digit alphabet is
\[
  D=\{0,\pm1,\pm\omega,\pm\omega^2\}.
\]
The norm of $\beta$ is seven.

The baseline uses 92 fixed positions.
The new construction uses 91 fixed positions for every scalar.
It keeps the same alphabet and input-label shape.
It also replaces the exceptional affine row with one complete homogeneous row.
The complete row increases the per-row adaptor count from nine to 13.
Shared garbling passes and parallel row execution offset this extra work.

\section{Four-corner GLV recoding}

Use the Eisenstein norm
\[
  Q(a,b)=a^2-ab+b^2.
\]
The relevant BN254 constants are
\begin{align*}
 A &=147946756881789319000765030803803410728,\\
 d &=9931322734385697763,\\
 C &=A+d,\\
 r &=A^2+Ad+d^2.
\end{align*}
The two GLV kernel vectors are
\[
  v_1=(-A,d),\qquad v_2=(-d,-C).
\]

Arkworks divides the two negative quotient numerators toward zero.
Thus, its GLV state is the floor representative $z_0$ used by the proof.
The selector checks
\[
  z_0,\quad z_0+v_1,\quad z_0+v_2,\quad z_0+v_1+v_2.
\]
Each shift is in the reconstruction kernel.
Thus, every candidate represents the same scalar.

For quotient remainders $u,v\in[0,r)$, scaling maps these four states to the four corners of one Eisenstein cell.
The two triangle lemmas show that one corner satisfies
\[
  3Q(a,b)\le r.
\]
This is the exact covering-radius step.

\section{Exact 91-round bound}

One recurrence round selects a unit digit and divides by $\beta$.
For a state with $Q(a,b)\le m$, the selected digit gives
\[
  Q(a-u_d,b-v_d)\le m+1+\lfloor\sqrt{4m}\rfloor.
\]
Exact division gives
\[
  Q(a-u_d,b-v_d)=7Q(a',b').
\]

Define the inverse safe bound
\begin{align*}
 B(0)&=2,\\
 B(n+1)&=7B(n)+1-\left\lfloor\sqrt{4(7B(n)+1)}\right\rfloor.
\end{align*}
Lean proves the generic induction rule
\[
  Q(a,b)\le B(n)\Longrightarrow \mathsf{after}(n+1,(a,b))=(0,0).
\]
It also checks
\begin{align*}
 B(90)&=8072890822786049911192470628436961768360750887255955910449276353626847573707,\\
 r&\le3B(90).
\end{align*}
The numeric proof uses ten-round kernel-checked checkpoints.
It does not use \texttt{native\_decide}.

The main Lean results are:
\begin{itemize}
  \item \texttt{shiftedInitialCorrect};
  \item \texttt{existsCandidateNormBound};
  \item \texttt{fourCandidatesSignedI128};
  \item \texttt{existsCorrectShiftedInitialTerminates91};
  \item \texttt{shortInitialTerminates91};
  \item \texttt{shortInitialCorrect}.
\end{itemize}
The axiom audit reports only \texttt{propext}, \texttt{Classical.choice}, and \texttt{Quot.sound}.

\section{Optimality}

Lean checks
\[
  7^{90}<r<7^{91}.
\]
A fixed 90-position string over seven symbols has at most $7^{90}$ values.
It cannot represent all $r$ scalars.
Thus, 91 is optimal for this fixed alphabet.

\section{Complete homogeneous addition}

Let the hidden offset be $K=(A:B:C)$.
Let $(u,v)$ be the selected endomorphism image of the evaluator input.
Use homogeneous coordinates for
\[
  Y^2Z=X^3+3Z^3.
\]
An affine point is $(x:y:1)$.
The group identity is $(0:1:0)$.

RCB Algorithm 7 gives these three polynomials:
\begin{align*}
 X={}&-9AB-18BCu-18ACv+(B^2-9C^2)uv+ABv^2,\\
 Y={}&-81C^2+27A^2u+27ACu^2+B^2v^2,\\
 Z={}&9BC+(B^2+9C^2)v+BCv^2+3A^2uv+3ABu^2.
\end{align*}
One fresh nonzero value $\rho$ multiplies all three coordinates.
This common factor preserves the represented projective point.
The zero digit returns $\rho(A,B,C)$.

The decoder keeps $Z$ until the final projection.
For $Z\ne0$, it validates $(X/Z,Y/Z)$ and returns that point.
For $Z=0$, it accepts only $X=0$ and $Y\ne0$.
This case returns the group identity.
It rejects all other zero-denominator triples.

Lean proves the homogeneous curve equation.
It proves that the output is nonzero and projectively nonsingular.
It then proves that projective decode equals Mathlib group addition for every valid affine pair.
The proof has separate cases for different x-coordinates, doubling, and inverse inputs.
The main results are:
\begin{itemize}
  \item \texttt{outputNonsingular};
  \item \texttt{outputRepresentsSum};
  \item \texttt{decodeHomogeneous\_eq\_toAffine};
  \item \texttt{decodeEvaluateRowSome};
  \item \texttt{decodeEvaluateRowNone};
  \item \texttt{perfectCorrectness}.
\end{itemize}
The axiom audit reports only \texttt{propext}, \texttt{Classical.choice}, and \texttt{Quot.sound}.

\section{Adaptor optimum}

The complete Bosma--Lenstra family has projective parameters
$[\alpha:\beta:\gamma]$.
Completeness requires $\beta\ne0$.
Normalize $\beta=1$.
Under the exact \texttt{Biquadratic} support rule, the adaptor counts are
\[
 D(0,0)=13,\qquad
 D(0,\gamma)=14\text{ for }\gamma\ne0,\qquad
 D(\alpha,\gamma)=15\text{ for }\alpha\ne0.
\]
Thus, RCB parameters $[0:1:0]$ give the unique minimum of 13.
This result covers fixed bidegree $(2,2)$ laws in the current masking architecture.

A second lower bound covers private role-preserving linear rows.
A row with $t$ scalar adaptors exposes $14+t$ selected field values.
Its adaptor randomness has dimension at most $2t-2$.
Only the three output coordinates can stay unmasked.
Thus, $2t-2\ge 11+t$, so $t\ge13$.
A correct ten-adaptor sharing attempt violates this bound and exposes four extra coefficient invariants.
The current row reaches 13.
This result does not exclude a nonlinear garbling architecture.

\section{Rust row parallelism}

The Rust implementation allocates one job for each output row.
It allocates the three child nonce domains before Rayon starts.
It samples one fresh 32-byte ChaCha12 root from the caller RNG.
Row $j$ uses stream
\[
  \mathtt{0x666d3265635f6d61}+j
\]
from word position zero.
Indexed collection keeps the row order.
Debug builds use the same RNG and nonce schedule in serial order.
Release builds use Rayon.

The root seed is erased after row construction.
Jobs borrow output keys.
They do not copy those secret keys into a second vector.
Fixed Boolean arrays replace heap-based coefficient index sets.
One byte packs each fixed-key level and digest-pair index.
Eight injective 54-byte inputs derive the 15 AES keys.
Each input and its padding fit in one SHA-256 compression block.
Each 256-bit digest supplies two 128-bit keys; one final half is unused.
The 384-bit hash-to-field reducer reads the three AES blocks directly.
It avoids generic slice loops and a 48-byte staging copy.
The 256-bit field pad uses four explicit little-endian limb XOR operations.
Tests compare one-worker and four-worker tables.
A second test compares all 273 allocated child nonces with the serial schedule.

On the same Apple M5, the ARMv8 AES benchmarks used 100 Criterion samples.
The incomplete 92-row serial baseline estimate was 15.934 ms.
The complete 91-row, 10-worker row mean is 2.876 ms.
Its 95 percent interval is 2.861 to 2.893 ms.
The complete row stage is 5.54 times faster than the serial baseline.
Direct field-limb XOR lowered its adjacent row mean by 8.7 percent.
Direct hash-block reduction then lowered its adjacent mean by 4.5 percent.
The one-block KDF lowered its adjacent mean by a further 8.7 percent.
Digest pairing then lowered its adjacent mean by 7.9 percent.

The protocol \texttt{encode} mean is 68.190 ms.
Its 95 percent interval is 67.963 to 68.581 ms.
The comparable baseline is 81.309 ms.
The complete implementation reduces this time by 16.1 percent.
Its HMAC table has 9,668,659 bytes.
This is 2,970,240 bytes larger than the incomplete 91-row table.

\section{Security scope}

The following invariants stay fixed:
\begin{itemize}
  \item Every candidate reconstructs the same scalar modulo $r$.
  \item Every public circuit has exactly 91 output positions.
  \item The digit alphabet does not change.
  \item The input keeps 508 Lamport label positions.
  \item The fixed-key window loads stay 91, 91, and 72.
  \item Every support flag is public and independent of the scalar.
  \item One nonzero factor scales all three homogeneous coordinates.
  \item Each row uses a separate nonce subtree and RNG stream.
  \item Worker order cannot change the table or caller RNG state.
\end{itemize}

The Rust selector uses four fixed 91-round tests and \texttt{subtle::Choice}.
This gives a fixed iteration count.
Lean proves that every tested coordinate fits a signed 128-bit integer.
